## 缺陷、修复和回归证据

### B-01 隔离数据库导出未 checkpoint 正确数据库（P0）

- 复现：用随机数据库名构造 Room 测试库，插入鱼缸/鱼只/养护记录后导出并 `inspect`。原实现总是 checkpoint `DatabaseFactory` 默认正式库，隔离库仍有未合并的 WAL 内容，备份校验报缺少必需数据表。
- 根因：`LocalBackupManager.export` 对非正式库名仍调用 `DatabaseFactory.create(context)`。
- 修复：正式库使用共享 `DatabaseFactory`；隔离库改用相同库名的 `databaseForRestore()` 再 checkpoint。
- 回归：修复后一次设备运行通过了数据库结构校验并到达压缩包文件名断言；后续完整备份往返因测试安装限制未重跑。原测试断言固定 `db/guanyji.db`，现改为隔离库名。

### B-02 恢复照片预校验检查了错误目录（P0）

- 复现：导出带原图和缩略图引用的隔离备份，再 `inspect`/`restore`。
- 根因：归档条目位于 staging 下的 `photos/...`，校验时去掉 `photos/` 前缀，改在 staging 根目录查找。
- 修复：按备份归档相对路径 `photos/...` 在 staging 中验证。
- 回归：新增照片原始字节和数据库鱼缸/鱼只引用完整性测试；修复后没有设备执行证据，**待复测**。

### B-03 成长测试夹具违反业务校验（P2，测试缺陷）

- 复现：测试调用 `saveGrowthRecord` 保存体长和体重都为空的记录。
- 根因：Repository 正确要求至少有一个有效测量，测试却把空记录当作“未知值可保存”。
- 修复：夹具改为未知体长 + 合法体重，并分别断言 NULL 和真实数值；未放宽业务校验。
- 回归：修正后 instrumentation 因设备阻塞未执行；测试源码编译成功。

### B-04 表单离开丢弃未保存内容（P1）

- 复现：在鱼只/鱼缸/水质/换水/喂食表单编辑字段，点返回或系统返回。
- 根因：返回处理直接执行 `popBackStack`，没有变更检测和确认。
- 修复：新增共享未保存离开保护，显示“放弃更改 / 继续编辑”；已接入上述表单并加 Compose 交互测试。
- 回归：主代码、UI 测试源码编译通过；手机未运行该 UI 测试，**待设备验收**。

### B-05 恢复失败不破坏当前库（P0）

- 复现：使用照片校验失败的备份调用 `restore`，检查当前数据库与照片。
- 根因：当前测试只验证 `inspect` 阶段失败，不验证 `restore` 的数据保护。
- 修复：扩展损坏包测试，使 `restore` 也必须失败且当前鱼缸/照片仍保留；另增加恢复照片完整往返测试。
- 回归：用例编译成功，设备执行仍被安装限制阻止；不能标记通过。

### B-06 隔离备份恢复遗留 Room 连接（P0）

- 复现：随机数据库名导出带照片引用的备份，删除当前记录后恢复，再通过新 Room 连接读取鱼缸封面。
- 根因：隔离路径的 `export`、恢复前 checkpoint 和恢复后引用验证分别创建 Room 实例但未关闭；替换 SQLite 文件后连接仍持有旧页缓存。
- 修复：隔离数据库的临时 Room 实例均在 `finally` 中关闭；默认正式库仍由 `DatabaseFactory` 管理。
- 回归：照片原始字节、缩略图字节、鱼缸/鱼只 photoId 往返单项设备测试 `OK (1 test)`；QA 完整运行中备份类均通过。

### B-07 备份测试夹具删除顺序违反外键（P2，测试缺陷）

- 复现：恢复主用例直接删除仍有鱼只引用的测试鱼缸。
- 根因：`fish.tankId` 为 RESTRICT 外键，夹具没有先删除测试鱼。
- 修复：先删除隔离测试鱼，再删除鱼缸；恢复后的鱼只和关联记录断言保持不变。
- 回归：修复后的 QA 全套运行中备份类通过。

### B-08 UTP 对默认 applicationId 自动卸载正式 App（P0，测试基础设施风险）

- 复现：默认 `com.guanyji.app` 的 `connectedDebugAndroidTest` 首轮安装测试 APK 失败后，UTP 日志随后执行 `Uninstalling com.guanyji.app`；`pm path` 一度无输出。
- 根因：该设备的 UTP cleanup 会卸载 target APK；Android 卸载可能删除应用私有数据库和照片。没有执行 `pm clear`，但不能证明卸载前数据未丢失。
- 处置：新增可选 Gradle property `acceptanceApplicationId`，通过 `-PacceptanceApplicationId=com.guanyji.app.qa` 构建和运行全量 QA，使自动清理仅针对 QA 包。最终正式 APK 通过 `adb install -r` 重装并确认包路径。
- 回归：QA runner 能发现并执行 41 项；不代表可恢复已被 Android 卸载清除的私有数据。正式数据仅能从用户已有备份恢复。

### B-09 Compose 导航 UI 测试在设备上超时（P1，设备/UI 自动化环境）

- 复现：完整 QA runner 到达导航页面切换测试后长时间无输出，最终进程崩溃；独立用例也曾失败。单独表单保护用例停在 Compose rule 启动阶段。
- 现象：主 Activity 可由 ADB 启动并截图，设备没有记录到 ANR；将 Activity 手动置前台及触摸导航均未解除测试等待。
- 处置：导航断言改为稳定标题；没有跳过或删除测试。需在模拟器或可稳定驱动 Compose UI 的设备复测。
- 回归：完整 QA 运行仍有 1 个导航 UI failure、2 个 UI 测试未完成。

## 手工验收步骤

若用户已有备份，先校验并通过应用恢复；不要以 QA 测试包覆盖正式数据。之后按以下步骤做尚未完成的真实场景验收。

1. 开启飞行模式首次启动，创建一个淡水缸和一个海水缸，退出并强停应用后重开；确认鱼缸仍在，未生成示例记录。
2. 添加鱼和照片，编辑照片、鱼种、入缸日期；分别验证归档、删除确认、转缸历史、任务关联和照片文件仍可加载。
3. 记录仅体长、仅体重和多条成长记录；更正及删除记录，切换 30 天、90 天、全部范围；空字段应为空，曲线只含真实测量。
4. 做单鱼喂食和一次关联多鱼的全缸喂食；核对鱼缸事件数增加 1 次及每条目标鱼摘要正确。
5. 淡水/海水表单检查参数单位、盐度与比重各自字段、空值和历史查询；容量未填写时记录换水，确认没有虚假比例，并核对实际完成时间与下次计划时间分开。
6. 创建一次性与重复任务，逐项完成、延期、跳过、取消；检查历史、后续 occurrence 唯一性。拒绝通知权限后继续使用应用内任务，再从系统设置打开权限重试。

## 剩余风险与建议

1. **P0 发布阻断：核对/恢复正式用户数据。** UTP 曾卸载正式包，私有数据库/照片可能被系统移除；仅凭 APK 重装不能证明数据完整。若有用户备份，先校验后通过应用恢复验证。
2. 开机 receiver、真实闹钟、强停/重启、厂商省电及权限允许流程没有端到端证据；单元测试 occurrence key 不能替代设备提醒恢复验收。
3. **P1：在稳定的 UI 自动化设备完成 Compose 测试。** 当前 MIUI 设备在导航用例等待约 753 秒后 runner 崩溃；导航 UI 方法失败，另 1 个导航与表单确认方法未执行。
4. 小屏、系统字体、主题矩阵、数据库写失败/存储不足、筛选和返回状态仍需手工验收。
5. connected 测试继续使用随机数据库/照片目录和 QA applicationId，避免测试框架卸载正式包。
