## 1. 总体结论

> **修复状态（2026-10-17 补记）**：本报告列出的 **P1-1、P1-2 与 P2-1～P2-5 已全部修复**，P3 清理完成 10 项。逐条说明、新配色实测对比度与最新验证结果见 **第 9 节**。第 2～8 节保留审计当时的判断与证据，便于对照。

## 3. 发现清单

### P1-1 徽标文字对比度不足，且比改动前更差（可访问性）

**位置**：`feature/tank/TankScreens.kt:138-142`（鱼缸卡状态徽标）、`core/designsystem/AquariumCardShell.kt:152-167`（类型徽标）、`ui/theme/AquariumCardTokens.kt:129-134`

**证据**（按 WCAG 2.1 相对亮度实算）：

| 组合 | 对比度 | 判定 |
| --- | --- | --- |
| 白字 / 新「在养」徽标 `#3FD0B6` | **1.92:1** | 不达标（AA 需 4.5，大字需 3.0） |
| 白字 / 新「已归档」徽标 `#6D8BB0` | 3.52:1 | 不达标 |
| 白字 / 旧「在养」徽标 `#16A98A` | 2.97:1 | 改动前也不达标，但明显更好 |
| 白字 / 旧「已归档」徽标 `#73869A` | 3.75:1 | 改动前略好 |
| 白字 / 类型徽标（淡水 `#1FAF9A`） | **2.74:1** | 不达标 |
| 白字 / 类型徽标（海水 `#2479DE`） | 4.32:1 | 不达标（临界） |
| 白字 / 旧类型徽标 `#1687E8` | 3.71:1 | 改动前更好 |

**影响**：`TankBadge` 用 `contentColor = Color.White` 画 11sp 标签（`TankScreens.kt:312`），在浅色强调色上几乎糊成一片；类型徽标 13sp 白字配淡水青绿同样读不清。`AGENTS.md`「页面设计与 UI 开发规则」明确要求「提供可访问的…对比度」。

**建议**：徽标改为「浅底深字」（如 `#0B3050` 文字 + 12% 强调色底）或提高底色不透明度并压暗强调色（淡水至少压到 `#0F7A6B` 级别）；把徽标前景/背景色一并放进 `AquariumCardTokens`，避免每处 `Color.White`。

### P1-2 「今日喂食」日界在 ViewModel 生命周期内被冻结

**位置**：`feature/tank/TankViewModel.kt:49`（`private val dayBounds = deviceDayBounds()`）、`:53`（`repository.feedingCountsByTank(dayBounds.first, dayBounds.second)`）

**证据**：`dayBounds` 是普通 `val`，在 ViewModel 构造时求值一次；`feedingCountsByTank` 的 Room `Flow` 因此永远带着同一对 `[今日0点, 明日0点)` 参数重新查询。`DeviceDayBounds.kt` 本身做了可注入设计并有单测，但 ViewModel 把「可注入的纯函数」当「一次性常量」用了。

**影响**：App 长时间驻留（或跨零点回到列表）后，鱼缸卡片仍显示前一天的喂食次数；同一天内新建/删除喂食事件能通过 Room 失效正确刷新，**只有跨自然日不刷新**，属于静默错误数据，用户难以察觉。

**建议**：把日界做成流，例如 `flow { while(true) { emit(deviceDayBounds()); delay(到下一个零点) } }.flatMapLatest { (s, e) -> repository.feedingCountsByTank(s, e) }`，或用 `Lifecycle`/页面 `onResume` 触发重算；`FishViewModel.dayBounds()` 目前也是同一模式（`FishViewModel.kt:63`），建议一并统一，避免两处口径不同。

### P2-1 鱼只状态色语义回归：已故 / 已归档与「在养」视觉无差别

**位置**：`feature/fish/FishCard.kt:130-155`（`FishCardStatus` 不再接收 palette）、`ui/theme/AquariumCardTokens.kt:112-114`

**证据**：`FishCardStatusBackground/Accent/Text` 直接绑定 `AquariumCardColors.StatusActive*`（`FishCard.kt:147` 用 `FishCardStatusAccent` 画圆点），于是 `已故`、`已归档`、`隔离`、`已转出` 全部渲染成同一枚青绿色胶囊。与此同时 `AquariumCardTokens.kt:101-102` 定义了 `NeutralStatusDot` / `NeutralStatusText`，`FishCardVisuals.kt:108-133` 的 `cardPalette()` 五套配色也仍然存在——说明这是一次**未完成的中性化重构**，落点接错了令牌。

**影响**：
- 设计文档 3.1 表格要求「异常状态同时配图标与文字」，现在异常状态既无图标也无色彩区分，只有文字。
- 列表里「已故」鱼只与「在养」鱼只在视觉上等价，信息层级反而下降。
- `FishCardVisualsTest.kt:88` 仍在断言五套 palette 互不相同，但 UI 已不再使用它，测试给出「已覆盖」的错觉。

**建议**：二选一并写清楚——(a) 真中性化：改用 `NeutralStatusDot/NeutralStatusText`，并给异常状态补 `FishIcons` 警示图标；(b) 保留状态色：让 `FishCardStatus` 继续吃 `cardPalette()`。同时删除或明确保留 `cardPalette()` 的用途，并调整对应测试。

### P2-2 鱼缸列表错误态无法恢复

**位置**：`feature/tank/TankViewModel.kt:69`、`feature/tank/TankScreens.kt:106-107`

**证据**：`cards` 用 `.catch { emit(TankCardsState.Failed(...)) }` 收尾，流一旦失败即终止，不会再发射成功值；页面把 `ErrorState(message)` 调用成 `onRetry = null`（`AppComponents.kt:60` 只有传了回调才画「重试」按钮）。对照组：同一文件 `TankScreens.kt:496` 的鱼只加载错误用了 `onRetry = vm::retryFish`。

**影响**：任一 Room 查询抛错后，鱼缸列表停留在一个**没有重试按钮、也不会自愈**的错误页，只能退出重进（甚至需要杀进程）。违反 `AGENTS.md` 第 9 条对错误状态的要求。

**建议**：加 `retry` 信号源（参考 `FishViewModel.fishRetry` 的写法），`catch` 之后 `emitAll(retry.flatMap { cardsFlow })`，并把 `onRetry` 接到 `ErrorState`。

### P2-3 鱼缸卡片绕过共享令牌，两卡排版参数不一致

**位置**：`feature/tank/TankScreens.kt:161-162`、`:173`、`:185-260` 等

**证据**：
- 文件新增了 `import com.guanyji.app.ui.theme.AquariumCardTokens`（`:46`）但**全文没有任何引用**——这是「本打算用令牌、最后落成硬编码」的直接痕迹。
- 面板内边距 `start = 11.dp, end = 11.dp, bottom = 10.dp`、行距 `5.dp`、图标 `18/14/13.dp`、徽标内边距 `8.dp` 全部字面量；而鱼只卡片用 `CardBodyInset = 8.dp`、`CardTextRowSpacing = 2.dp`、`CardArrowSize = 18.dp`。
- 字号也不统一：鱼缸卡用 `MaterialTheme.typography.labelSmall/labelMedium/titleSmall`，鱼只卡用 `AquariumCardTokens.CardTitleFontSize` 等显式 token。

**影响**：同屏两张卡片（「我的鱼」与「鱼缸」）在相同信息层级上留白与字号不同；令牌体系因此无法真正成为唯一真源，后续改视觉要改两处。`AquariumCardTokens` 里同时存在 `FishCard*` 与 `TankCardPanelInset` 两套命名，方向是对的，但没被用起来。

**建议**：把鱼缸卡的 11/10/5/13/14/18 等换成 `CardBodyInset`、`CardTextRowSpacing`、`CardArrowSize`、`CardMetric*`；如确需差异，新增显式的 `TankCard*` 令牌而不是字面量。

### P2-4 同一语义标签存在两套配色来源

**位置**：`feature/tank/TankScreens.kt:133-142`（列表卡）对比 `TankScreens.kt:486-487`（详情页）

**证据**：详情页仍是 `TankBadge(if (tank.type == TankType.freshwater) "淡水缸" else "海水缸", Color(0xFF1687E8))` 与 `Color(0xFF16A98A)` / `Color(0xFF73869A)`；列表卡则用 `AquariumTypeBadge` + `AquariumCardColors.FreshwaterAccent/SaltwaterAccent/StatusActiveAccent/StatusArchivedAccent`。同一句「淡水缸」在详情页是蓝色、在列表卡是青绿色；同一句「在养」在两处是两种绿。
